- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：
    - 出力フォーマット（JSON、YAML等）の厳格な遵守や、特定の口調、キャラクター、手順（推論パターン）を固定化させる用途。
    - 毎回プロンプトに長いルールや Few-shot を記述するコンテキストコストを削減したい用途。
  - 向かない場面：
    - 平文の事実データを大量に学習させると、プロンプトで与えた JSON 指示を上書きし、覚えた平文をそのまま吐き出すようになってしまう（形式の忘却）。形式を保つには形式学習データとの混合が必要となる。
    - ファインチューニングで知識を刷り込んでも、モデルは「自分が何を知っていて、何を知らないか」の境界を判断できない。未知の問いに対して「知らない（確認が必要）」と言えず、学習した重みから確率的にそれらしい嘘をついてしまう。
    - 用語集やマニュアルが更新されるたびに再学習が必要となり、保守性が低い。
  - 用語集検索（RAG / MCP）との比較：
    - 用語集のような「事実データ（ナレッジ）」の参照には、ファインチューニングよりも RAG や MCP（Tool use）を用いる方が適している。
    - 検索によって外部から最新の定義文をプロンプトに直接注入するアプローチを採ることで、モデルに無理な暗記を強いずに済み、更新の即時反映が可能になるとともに、根拠に基づかないハルシネーションを抑止できる。
